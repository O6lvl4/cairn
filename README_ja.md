# agent

[Almide](https://github.com/almide/almide) で書かれたコーディングエージェント。単一の静的バイナリで、
入れるべきランタイムはありません。書き込みを止める構文ゲートも、ファイルを見せるリーダも、失敗を
圧縮する要約器も、すべて同じ言語のプログラムです。

```
agent solve "clamp のテストが範囲外の値で落ちる" --root ../project
agent observe --root ../project     モデルに聞かずに分かることを全部
agent llm-test                      1 回だけ呼んで資格情報を確かめる
```

## 何をするか

先に観察し、それから動きます。依存する対象を見るまで何も決めず、モデルには小さな問いを一つずつ渡します。

1. **観察** — マーカーファイル、言語、成功を決める検証コマンド、ファイル一覧、順位付きリポジトリ地図、
   そして落ちているテストの実際の出力。すべて調べた事実で、推測はしません。
2. **選択** — どのファイルを読むか。丸ごと読める小さなプロジェクトは丸ごと読み、モデル呼び出しをしません。
3. **編集** — モデルは完全なファイルを返します。構文ゲートを通して 1 ファイルずつ書き、パースできない
   ものは拒否します。隣の悪い編集が拒否されても、良い編集は着地します。
4. **検証** — もう一度コマンドを実行。落ちたテストは安いモデルが使える情報です。梯子を登るのは
   **使えない出力**のときだけで、そのあとに強いモデルへ。

試行の間には、実際に何を変えたか（unified diff）、何がなぜ拒否されたか、コンパイラ自身による
診断コードの説明を渡し、同じ失敗が続いたときは「調整ではなく置き換えろ」と伝えます。

## なぜ Almide

移植元の TypeScript 版 famulus5 は、オープンウェイトのモデルで Aider polyglot ベンチマーク 84〜85%。
ただし Node と、構文ゲートのための tree-sitter のネイティブ文法が必要でした。こちらは単一バイナリで、

- **[gramide](https://github.com/O6lvl4/gramide)** — 構文ゲートとリポジトリ地図。Almide 製のパーサで、
  コーパス検証済み、ネイティブライブラリなし。
- **[peek](https://github.com/O6lvl4/peek)** — 構造を意識した読み取り（入っていれば）。
- **[ctxgate](https://github.com/O6lvl4/ctxgate)** — 判定を先に置く失敗要約（入っていれば）。

いずれも任意です。バイナリが無ければ組み込みの経路に落ちるだけで、エラーにはなりません。

## 現状

正直に言うと、これは移植であり、移植元との比較はまだ測っていません。ループも防御も再試行方針も
famulus5 が測ったものですが、同じスコアが出るかは未解決で、`bench/almide.sh` がその答えを出す場所です。
種を仕込んだバグの確認は通ります（1 試行、5 秒、0.02 セント）。

## ビルド

```
almide build          # → ./agent
almide test           # 7 モジュール
```

資格情報は環境変数か、プロジェクト脇の `.env` から。`CLOUDFLARE_ACCOUNT_ID` と `CLOUDFLARE_API_TOKEN`。

## 構成

| ファイル | 中身 |
|---|---|
| `src/llm.almd` | Workers AI 呼び出し。常にストリーミング、コストは `neurons`、途中切れはエラー |
| `src/ask.almd` | スキーマ付きの問いと再試行方針（408 は**小さく**して再試行） |
| `src/observe.almd` | マーカー、ファイル一覧、コマンド実行、ハーネスが壊れている条件 |
| `src/explain.almd` | `almide explain` / `rustc --explain`、失敗のどこを見せるか |
| `src/gate.almd` | 書き込みゲート。パースできないものは着地しない |
| `src/solve.almd` | ループ |
| `src/main.almd` | CLI |
